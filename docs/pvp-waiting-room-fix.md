# Исправление проблемы с обновлением состояния комнаты ожидания в PvP

## Описание проблемы

При дуэли в PvP арене один игрок запускался в матч, а другой продолжал ожидать соперника. Проблема решалась только перезагрузкой или повторным открытием PvPTab.

### Корень проблемы

Находясь в комнате ожидания, система не запрашивала состояние комнаты постоянно, как это происходило в BattleInterface от PvPTab или в уже начавшемся бою.

**Отсутствовало периодическое обновление состояния для комнат в статусе "waiting".**

## Техническое решение

### Анализ существующей архитектуры

В `src/components/tabs/PvPTab.js` были следующие механизмы обновления:

1. **Обновление списка комнат** (строки 1318-1320): 
   - Условие: `activeTab === 'rooms'`
   - Интервал: каждые 5-15 секунд

2. **Обновление состояния боя** (строки 1658-1818):
   - Условие: `inBattle === true`
   - Интервал: каждую секунду

3. **Отсутствовало**: обновление состояния комнаты ожидания
   - Условие: `selectedRoom !== null && inBattle === false`

### Реализованное решение

Добавлен новый `useEffect` для периодического обновления состояния комнаты ожидания:

```javascript
// Обновление состояния комнаты ожидания
useEffect(() => {
    const updateWaitingRoomState = async () => {
        try {
            // Проверяем условия
            if (!selectedRoom || inBattle) return;
            if (roomDetails?.room?.status && roomDetails.room.status !== 'waiting') return;
            
            // Запрашиваем актуальное состояние комнаты
            const response = await getRoomDetails(selectedRoom);
            
            if (response.success) {
                // Обновляем детали комнаты
                setRoomDetails(response);
                
                // Проверяем переход в бой
                if (response.room.status === 'in_progress') {
                    setInBattle(true);
                    setBattleState(response);
                    
                    // Устанавливаем lastActionId для боя
                    if (response.actions?.length > 0) {
                        setLastActionId(Math.max(...response.actions.map(a => a.id)));
                    }
                    
                    showToast('Бой начался! Переходим в режим боя...', 'success');
                }
            }
        } catch (error) {
            console.error('Ошибка при обновлении состояния комнаты ожидания:', error);
        }
    };
    
    // Условие: в комнате, но не в бою
    if (selectedRoom && !inBattle) {
        updateWaitingRoomState();
        const interval = setInterval(updateWaitingRoomState, 1000);
        return () => clearInterval(interval);
    }
}, [selectedRoom, inBattle, player.id]);
```

### Ключевые особенности решения

1. **Условия активации**:
   - `selectedRoom !== null` (игрок находится в комнате)
   - `inBattle === false` (бой еще не начался)
   - `roomDetails?.room?.status === 'waiting'` (комната в ожидании)

2. **Частота обновления**: каждую секунду (как в бою)

3. **Автоматический переход в бой**:
   - При изменении статуса с 'waiting' на 'in_progress'
   - Плавная передача состояния в `battleState`
   - Установка `lastActionId` для корректного обновления боя

4. **Обработка ошибок**:
   - Логирование для отладки
   - Отсутствие навязчивых уведомлений при фоновых ошибках

5. **Оптимизация производительности**:
   - Минимальные зависимости в useEffect
   - Проверка условий перед выполнением запросов
   - Корректная очистка интервалов

## Результат

После внесения изменений:

✅ **Игроки автоматически переходят в бой** при присоединении второго игрока  
✅ **Состояние комнаты обновляется в реальном времени** без необходимости перезагрузки  
✅ **Плавный переход** из режима ожидания в режим боя  
✅ **Консистентность** с существующей архитектурой обновления состояния боя  
✅ **Оптимизированная производительность** без лишних запросов
