# Руководство по настройке HTTPS для приложения

## Обзор

Данное руководство описывает настройку HTTPS для webpack dev server с использованием SSL сертификатов.

## Что было настроено

### 1. Конфигурация webpack dev server (craco.config.js)

- **Порт изменен с 80 на 443** (стандартный HTTPS порт)
- **Добавлена поддержка HTTPS** с SSL сертификатами из папки `ssl/`
- **Обновлены proxy настройки** для корректной работы с HTTPS → HTTP проксированием

```javascript
devServer: {
  port: 443,
  https: {
    key: path.resolve(__dirname, 'ssl/culty.ru.key'),
    cert: path.resolve(__dirname, 'ssl/culty.ru.crt')
  },
  proxy: {
    '/api': {
      target: 'http://localhost:3001',
      changeOrigin: true,
      secure: false // Разрешаем проксирование с HTTPS на HTTP
    }
  }
}
```

### 2. Переменные окружения (.env)

Добавлены новые переменные:
- `HTTPS=true` - включает HTTPS режим
- `REACT_APP_PORT=443` - обновлен порт приложения
- `SSL_CRT_FILE=ssl/culty.ru.crt` - путь к сертификату
- `SSL_KEY_FILE=ssl/culty.ru.key` - путь к приватному ключу

## Запуск приложения

### Обычный запуск
```bash
npm start
```

Приложение будет доступно по адресу: `https://localhost:443`

### Запуск с API сервером
```bash
npm run dev
```

Это запустит одновременно:
- React приложение на `https://localhost:443`
- API сервер на `http://localhost:3001`

## Важные замечания

### 1. Права администратора
На Windows для использования порта 443 может потребоваться запуск терминала от имени администратора.

### 2. Предупреждения браузера
При использовании самоподписанных сертификатов браузер может показывать предупреждения о безопасности. Это нормально для разработки.

### 3. API проксирование
API запросы автоматически проксируются с HTTPS на HTTP сервер:
- Клиент: `https://localhost:443/api/*`
- Сервер: `http://localhost:3001/api/*`

## Структура SSL сертификатов

```
ssl/
├── culty.ru.crt    # SSL сертификат
└── culty.ru.key    # Приватный ключ
```

## Возможные проблемы и решения

### Ошибка "EACCES: permission denied"
**Решение:** Запустите терминал от имени администратора

### Ошибка "EADDRINUSE: address already in use"
**Решение:** Убедитесь, что порт 443 не используется другими приложениями

### Предупреждения о сертификате
**Решение:** В браузере нажмите "Дополнительно" → "Перейти на localhost (небезопасно)"

## Возврат к HTTP

Если нужно вернуться к HTTP:

1. В `craco.config.js` измените:
   - `port: 80`
   - Удалите секцию `https`
   - В proxy уберите `secure: false`

2. В `.env` измените:
   - `HTTPS=false` (или удалите строку)
   - `REACT_APP_PORT=80`

## Дополнительная информация

- SSL сертификаты действительны для домена `culty.ru`
- Сертификаты самоподписанные, подходят для разработки
- Для продакшена рекомендуется использовать сертификаты от доверенного CA

## Упрощенная Docker HTTPS архитектура

### Почему без nginx?
Webpack dev server уже умеет работать с HTTPS напрямую, поэтому nginx здесь избыточен. Прямое подключение к webpack dev server:
- Проще в настройке и отладке
- Меньше промежуточных слоев
- Лучшая производительность для разработки
- Автоматическая поддержка hot reload через HTTPS

### Финальная конфигурация Docker

**docker-compose.yml:**
```yaml
app:
  ports:
    - "443:443"    # HTTPS webpack dev server
    - "3001:3001"  # Express API server
  volumes:
    - ./ssl:/app/ssl:ro  # SSL сертификаты
  environment:
    - REACT_APP_PORT=443
    - HTTPS=true
    - SSL_CRT_FILE=ssl/culty.ru.crt
    - SSL_KEY_FILE=ssl/culty.ru.key
```

### Архитектура подключений

```
Браузер → https://your-server:443 → Docker Container → Webpack Dev Server (HTTPS)
                                                    ↓
                                                API Proxy → Express Server (HTTP:3001)
```

### Преимущества такой архитектуры:
1. **Простота** - один сервер вместо двух
2. **Производительность** - нет дополнительного проксирования
3. **Hot Reload** - работает напрямую через HTTPS
4. **Отладка** - проще диагностировать проблемы
5. **Безопасность** - SSL терминация на уровне приложения

### Запуск в Docker:
```bash
docker-compose up --build
```

Приложение будет доступно:
- Локально: `https://localhost:443`
- В сети: `https://your-server-ip:443`
